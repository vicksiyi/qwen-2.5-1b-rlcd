# 海龟汤主持人：本地 Qwen + RLCD

执行 `./start.sh`，访问 <http://127.0.0.1:8000/turtle.html>。全部使用本地 Qwen2.5-1.5B-Instruct 4bit 和现有 `run_parallel_generation()`，无需 API 密钥。

## 录入自己的汤面和汤底

1. 在题目下拉菜单中选择“录入汤面与汤底”。
2. 填写可选汤名、必填汤面（最多 1,500 字符）、必填汤底（最多 5,000 字符）。汤底应明确说明人物、事实和因果关系。
3. 点击开局。录入框会清空并收起，玩家界面只显示汤面。
4. 出题人将页面交给玩家，玩家通过是非问题寻找真相。

自定义题只存在本地服务内存中，不保存到文件或发送至外部模型。刷新页面会丢失前端当前局入口；服务重启清空全部局，闲置两小时过期。当前不支持保存题库或恢复存档。

本机开发工具、原始录入请求和源码不属于防作弊边界。普通开局/问答响应不包含汤底、事实列表、提示词；揭晓或提交还原被模型判定成功后，才会返回汤底。

## 游戏功能

- 三道内置题，支持随机开局。
- 玩家一次提一个是非问题，主持人返回：是、否、无关、需要澄清、无法确定。
- 展示问答记录、问题次数、模型评分耗时及五类候选分数。
- 内置题提供三条逐渐明确的预设提示；自定义题未提供提示编辑，因此提示按钮禁用。
- 切换“提交还原”后，模型判断解释是完整、部分正确、冲突、模糊还是不确定。
- 普通问答中完整说出真相，也会自动提示“恭喜，你已经完全猜出答案了！”，不必切换到提交还原。
- 完整性检查将当前表述与最近最多 12 条得到肯定回答的玩家问题合并，对照关键因果点逐项评分；不把主持人的提示当作玩家已经猜到的内容。全部关键点通过才揭晓。已判定与事实矛盾的问题不触发通关。
- 内置题使用人工定义的关键点，自定义题按汤底标点切分（合并为最多 12 组）。自定义汤底中的附加细节也可能被要求还原，因此建议简洁说明核心因果关系。
- 每轮可能增加一次批量完整性评分；界面耗时包含回答与完整性检查。模型仍可能误判，最终可对照汤底核实。
- 每局最多 80 轮（包含提示和猜测），上限后仍可揭晓。服务最多保留 64 个未过期会话。

## 模型如何主持

程序不通过关键词表直接判断事实真假。它把服务端隐藏事实、最近最多六条记录中保留的问答以及当前玩家文本交给模型，让 RLCD 对有限回答候选评分。

普通问题使用 `yes / no / other / ask / unknown` 五个语义标签；当前 tokenizer 中它们各是不同的单 token，调用时仍会检查。相比抽象 A/B/C 编码，语义标签可以减少小模型在映射回答类别时的错误。服务端映射为中文回答，不输出自由生成的解释，减少额外泄漏汤底的机会。

提交还原使用另一组 A–E 候选，提示词额外提供完整还原应涵盖的关键因果点。自定义题将用户录入的汤底作为事实和还原依据。

每次正常问答/还原都执行真实模型推理；固定提示不调用模型。GPU 锁与项目其他功能共享；同一局禁止同时提交两个动作，失败推理不会写入问答记录。

分数是候选集合内归一化的模型偏好，不是正确率。结构约束只限制输出格式，不能保证语义正确。当前 1.5B 模型仍可能误判、受错误历史或诱导提问影响，也可能错误地判定还原成功。这里没有训练新权重、外接更大模型或实现独立事实验证器。

## 主要文件

- `server/turtle/stories.py`：服务端内置汤题、汤底、事实和提示。
- `server/turtle/api.py`：会话、输入校验、提示词、评分、回答与揭晓。
- `web/turtle.html`、`web/turtle.css`、`web/turtle.mjs`：录入表单与游戏页面。
- `tests/test_turtle.py`：汤底不提前返回、自定义输入、会话锁、提示上限、成功/失败还原及结束状态测试。

接口：

```text
GET  /api/turtle/stories
POST /api/turtle/new
POST /api/turtle/{game_id}/turn
```

自定义开局请求：

```json
{
  "story_id": "custom",
  "title": "关着的门",
  "surface": "门没有打开，小猫却离开了房间。为什么？",
  "solution": "窗户开着，小猫从窗户跳出了房间，没有人打开房门。"
}
```

提交问题：

```json
{"kind":"question","text":"小猫是从窗户离开的吗？"}
```

`kind` 还支持 `guess`、`hint`、`reveal`。回答以及候选分数包含在响应 `history` 的最后一条。

测试：

```bash
.venv/bin/python -m unittest discover -s tests -p 'test_turtle.py' -v
```

游戏为本地单机 Demo，不具备多用户账户、持久化、公开部署鉴权或可靠的反作弊机制。


## 本次验证

- 6 项海龟汤接口测试通过，覆盖自定义录入、汤底不提前返回、并发提交保护、推理失败不写历史、提示与轮数上限、还原及揭晓后的状态。
- 真实本地推理验证了内置题的“盲人”“作弊”“触摸批改”“隐形墨水”等明确事实判断，以及完整答案提交。
- 自定义“关着的门”中，“猫从窗户离开吗”回答“是”，“有人打开房门吗”回答“否”。
- 真实浏览器验证了录入、开局后清空汤底、问答、五类评分展示、揭晓、结束后禁止追问及手机宽度布局。

这些是少量功能与案例验证，不代表模型在任意汤题上的准确率。例如开放式问题“学生叫什么名字”被回答为“无法确定”，没有稳定区分“需要澄清”和“未设定”。复杂否定、多问合一及诱导提问仍需要人工核对。
